Make ./linux-check.sh run again: check.sh's mdlinks needs a git repository the container's tree lacks

Seen in item 3pund6 (2026-11-19): `./linux-check.sh` exits 2 in its first (epoll) run with `mdlinks: git ls-files: exit status 128`. linux-check.sh copies the tree into the container as a tar of `git ls-files --cached --others --exclude-standard` (linux-check.sh, the `docker run ... tar -xf /tree.tar -C src && cd src && ./check.sh` line), with no `.git`, while check.sh runs `bench/mdlinks/mdlinks`, which lists the Markdown files with `git ls-files` (added in 3dbc67e, item g4vate, after the last Linux run of 7b4e08f). So the Linux validation that AGENTS.project.md requires at each zio update cannot pass as committed.

Item 3pund6 ran a copy of the script outside the repository that adds `git init -q && git add -A &&` before `./check.sh` in the container (the image has git); both backends then passed. That is one option: the index then lists exactly the files the tar carried, which is the set the host's mdlinks sees. Another: let mdlinks take its file list from an argument or environment variable that linux-check.sh fills from its own list. Question for the owner: which, or another?
