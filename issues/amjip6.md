Give the container scripts run-scoped image tags, so overlapping runs never build or run another run's image

Split from lmbozk. Decided 2026-11-19 by the coordinating session with sol, argon and hydrogen (calls 964aa59f, a7443db6, 932242ab; all three agree it is a real race worth fixing now) under the user's delegation to decide the next tasks with the models. linux-check.sh, bench/arena/local.sh and bench/parse/profile.sh tag their images with fixed names (`lsrv-linux-check`; profile.sh's image is `FROM lsrv-linux-check`), while several sessions and rr2 worktrees run them against one Docker daemon on this Mac. One run's `docker build` can retag the image another run is about to start, or profile.sh can build on a base built from another worktree's linux/Dockerfile.

Work: each run uses exactly the image it built: capture the image ID (`docker build --iidfile`) or use a run-scoped tag, run that, and pass the base image to bench/parse/profile.sh's Dockerfile through a build argument (`ARG BASE_IMAGE`, `FROM ${BASE_IMAGE}`), so its FROM resolves to this run's base. Remove run-scoped tags the run created when it ends (only those). Keep the cache volume as is. No sleep, lock-and-retry or serialization as the fix (Rule 10). Test: two overlapping builds whose linux/Dockerfile differ by a marker; each run's container reports its own marker. Update README "Running".
