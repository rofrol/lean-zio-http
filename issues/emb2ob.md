Make the transport tests' TCP send-buffer premises hold on Linux

Seen in ogcdwm (2026-11-17), diagnostic `zig build test` in zig/ in an arm64 Debian container under OrbStack (kernel 7.2.12-orbstack, Zig 0.17.1, zio 830564437b2c, backend forced to epoll): serve_test.zig 19/22 pass. The Unix-domain parked-send test passes. Three TCP tests fail on premises checked only on macOS:

- "a write deadline the loop runs before a ready send's completion closes ..." and "a partial send's completion the loop runs before a due write deadline is reported ..." fail in `partialSend` at serve_test.zig:1382, `sndbuf < @min(response_len, 8192)`: Linux doubles a requested SO_SNDBUF and getsockopt returns the doubled value (socket(7), SO_SNDBUF), so the 4096 asked (`small_buffer`) reads back as 8192. Beyond the assertion, Linux TCP's send buffer is a soft limit (tcp_sendmsg checks free memory only before a new skb), so "a send writes at most the room in the buffer" may not bound a completion below `asked` there; not yet checked by a run.
- "a send that fails while the poll beside it is in flight closes only after the poll's completion" fails at serve_test.zig:1277 (`PollNeverStarted`; events: open, written): the whole 1 MiB response was sent without a send parking. The test sets only the client's SO_RCVBUF, not the server's SO_SNDBUF; the container's tcp_wmem is `4096 16384 4194304`, so autotuning can grow the server's send buffer past 1 MiB. Hypothesis consistent with that, not yet confirmed by a trace.

Options: (1) restate these tests on Unix-domain sockets, whose room is freed only at the peer's read on both XNU and Linux (as the parked-send test does); (2) keep TCP and set per-OS buffer premises (server SO_SNDBUF in the third test, the doubled value in the first two), checked by runs on both; (3) mark them macOS-only. Depends on the item that decides the Linux backend (epoll or io_uring).

Decided 2026-11-17 by the coordinating session with sol (consult call 88b30b66) under the user's delegation: option (1). Restate the three tests on Unix-domain pairs, asserting the actual partial write or blocked send (a positive event), not configured buffer sizes. Keep a separate TCP smoke or integration test on Linux, since Unix-domain coverage does not establish TCP behaviour. Verify on macOS and in the OrbStack Linux container (see ogcdwm).
