Make a failed transport test leave no state that fails the tests after it

Seen in item j3avm2 (2026-11-17): with the listener's TCP_NODELAY disabled on purpose, the new test in zig/src/serve_test.zig failed at its assertion, and seven later tests then failed in `Single.init` (zig/src/serve_test.zig, `expectEqual(0, serve.slots_used...)`: "expected 0, found 2"), and the multi-loop admission test panicked. A test that returns early through `try` skips the stop and `finish`, so the connection slots it took stay counted in the global `serve.slots_used`. One real failure then reads as eight. The consult round 20261117-101801-ed1b (sol) said the same thing. Options: give `Single.deinit` the job of draining what is still open (stop, run the loop to its end), or reset the global counters in `init` and report the leak there, or leave it as is.
