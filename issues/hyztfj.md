Trace why `zig build test` prints "failed command:" for the passing serve_test step

Seen by item jexowc on 2026-11-19 (Zig 0.17.1, macOS): every `./bench.sh` run and a direct `zig build test --summary all` in zig/ print, under "+- run test serve_test stderr", the lines the accept back-off tests provoke on purpose (serve_test.zig:2056-2062, `fail_accept_with = error.SystemResources`; serve.zig:940 "accept: ...; backing off until an accept succeeds") followed by "failed command: ./.zig-cache/o/.../serve_test --cache-dir=./.zig-cache --seed=... --listen=-", while the same run's summary says "Build Summary: 9/9 steps succeeded; 85/85 tests passed" and "run test serve_test 45 pass (45 total)", and the exit status is 0. So it does not mark a failure, but a reader of the log sees "failed command". Zig's runner prints `result_failed_command` with any step's stderr (lib/zig/compiler/Maker.zig:3393-3399) and clears it on success (Maker/Step/Run.zig:737); why it is still set for this zig_test step was not traced.

Options: trace it in Zig's build runner and, if it is a bug there, report it upstream (outward, the owner's go) | have the back-off tests not print (route the message through a test hook) so a passing run's log carries no "failed command" | leave it and note it in docs/running.md.
