Decide whether the type, not a comment, should keep the clock out of the adapter's kept state

Seen while doing daaqgn (commit a7d6c0b). `Server.Transport.Adapter σ := Nat → Server.Adapter σ` builds the adapter for each event's time, so a state kept by one time's adapter is handed to the next. Conn's theorems hold for one fixed adapter, so they describe the transport only if `init` and the kept state do not depend on the clock. Today that holds (H1Adapter and HandParser pass `now` only to the response writer) and is written in Transport's docstring, but nothing enforces it. Option: move the clock into `Server.Adapter.handle` as an argument used only for replies, or into the Reply construction, so the adapter is one value; that changes the core contract `Server.Wire` and needs the owner's approval.

Decided 2026-11-17 by the coordinating session with sol (consult round 20261117-025619-5ef1), under the user's delegation of the same day: approved. One adapter value; event time passed explicitly only to reply handling and construction. Establish that initialization is clock-independent and that successive transitions keep the connection invariant for arbitrary event timestamps; update transport-level proofs and both adapters. No unrelated redesign.
