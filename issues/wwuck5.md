The module boundary check accepts any App.* module without a rule

Moved on 2026-11-16 from ekklesiai.org's queue, where it was item kojbua (moved by its item m4jfmv). Item ids and decisions (D1, D2) named below are ekklesiai.org's; paths are this repository's.

Seen while designing gm6krq (design round 20261116-132811-60ca, sol; checked in `Arch.lean:38`): `rule` gives every module under `App` the rule "imports Server.Handler, Server.Query or any App module", so a new App module needs no entry in the map and any application may import any other. The check's own doc comment says a file no rule names fails. Proposal: name each App module in the table with what it may import, and test the checker on fixtures with deliberately forbidden imports (an unregistered module, an App module importing the transport). This item is the library's half; ekklesiai.org's copy (`site/Ekklesiai/Arch.lean`) already names each of its modules and keeps its own item for the fixture test.

Decided 2026-11-16 by this session with sol (consult round 20261116-145342-a8e2), under the user's delegation of that day to decide with sol what comes next: approved. Scope: name each existing App module in the table with exactly the imports it has now, and add checker fixtures that must fail (an unregistered module, an App module importing the transport).
